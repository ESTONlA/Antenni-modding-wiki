Getting Started

LOCLM gives your DLL a chance to edit the game before launch.

A mod is not running inside the game loop by default. It is loaded by LOCLM while the loader is building the patched cache file.

The full flow

  1. LOCLM reads the original game data.The original data.win is the input. Mods should not edit it manually.
  2. LOCLM scans loclm/mods/.Each mod should have its own folder with a matching DLL and modinfo.json.
  3. The loader validates metadata and dependencies.Disabled, blocked, incompatible, or missing-dependency mods can be skipped before patching.
  4. The mod DLL is loaded.LOCLM finds the public Load(int audiogroup, UndertaleData data) method.
  5. Your mod patches UndertaleData.You can change strings, code entries, sprites, sounds, objects, and rooms through UndertaleModLib data structures.
  6. LOCLM writes the cache file.The game starts from the generated cache, not from a manually edited original file.

What your mod should not assume

Game resources can change after updates.

A code name, script body, sprite name, or room layer can be changed by a game update. That is why Require* helpers fail loudly instead of silently doing nothing.

  • Do not assume a find/replace search string will last forever.
  • Do not assume your install path matches another user's Steam path.
  • Do not assume another mod has not patched the same code entry.
  • Do not assume a runtime file exists unless you ship it in assets/.

Mental model for beginners

Think of a LOCLM mod as a patch script for data.win. Your DLL runs, changes the loaded data, then exits. The result is saved into the generated cache file and the game starts from that patched data.

If you want behavior while the game is running, patch GML.

C# runs during the loader patch phase. GML hooks run later inside the game.
