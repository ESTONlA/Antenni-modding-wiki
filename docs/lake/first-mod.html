Lake / First mod
Tutorial

Build a small Lake mod first

Prove the complete load path with a renamed template and a log message before attempting a large gameplay patch.

1. Copy and rename the project

Copy mod_template/ to a new working directory. Rename the project file, output folder, namespace, public class, and manifest. Keep ModContext.cs until you intentionally replace its helper layer.

namespace BetterBoats;

public class BetterBoats
{
    public void Load(int audiogroup, UndertaleData data)
    {
        if (audiogroup != 0)
        {
            return;
        }

        ModContext context = ModContext.Create(data);
        context.Log("BetterBoats is patching Lake of Creatures.");
    }
}

2. Set the manifest

{
  "name": "Better Boats",
  "author": "Your Name",
  "description": "A first Antenni test mod.",
  "supportedGames": ["lake-of-creatures"],
  "priority": 100
}

The loader discovers the public Load method. The audiogroup != 0 guard prevents the same main patch logic from running for every audio group pass.

3. Remove the sample menu patch

If you only want to verify loading, remove the InstallMainMenuTab call and its method. This avoids claiming the sample button indexes and changing Lake menu code before your own feature needs it.

4. Build and install

dotnet build .\BetterBoats.csproj -c Release

Copy the generated BetterBoats/ directory to Lake of Creatures/antenni/mods/BetterBoats/. Delete no original game files.

5. Verify the load

  1. Launch LakeStart through Steam so the proxy uses the expected executable.
  2. Read the consoleFind the mod name, hash, security result, and load duration.
  3. Read ANTENNI.logConfirm your context.Log message appears.
  4. Read mod_status.jsonConfirm the mod is loaded rather than failed, skipped, blocked, or disabled.

6. Add one guarded change

Use a Require... helper for the target and make one narrow patch. If the resource name is wrong, fail with a useful message rather than silently producing a broken cache.

UndertaleCode target = context.RequireCodeEntry(
    "gml_Object_obj_ctrl_main_menu_Step_0");

context.Log($"Found patch target: {target.Name.Content}");
Change one thing per test

When the cache fails, a one-change build gives you a clear cause. Large first patches turn resource names, GML syntax, and loader behavior into one debugging problem.

Common mistakes

  • The output folder and primary DLL do not have matching names.
  • supportedGames explicitly contains only the Ogre game ID.
  • Only the DLL was installed, leaving required assets or dependencies behind.
  • The old CreatureProbe namespace or class name remains in one source file.
  • The sample Lake menu indexes conflict with another installed mod.
