Building and release

Ship the exact folder you tested

A release is a complete Antenni mod directory, not a loose DLL and not the entire source repository.

Build Release configuration

dotnet build .\YourMod.csproj -c Release

Install the output into a clean antenni/mods/ directory and test it before creating an archive.

Expected package

YourMod/
|-- YourMod.dll
|-- YourMod.deps.json
|-- modinfo.json
|-- UndertaleModLib.dll
|-- Underanalyzer.dll
|-- GameSpecificData/
`-- assets/
    |-- code/
    |-- data/
    |-- included/
    |-- sounds/
    `-- sprites/

Exact files depend on your project and used helpers. Debug symbols such as .pdb are optional for users but useful when you need actionable crash reports.

Pre-release checks

  1. Clean buildDelete stale output and build Release again.
  2. Manifest checkIf the mod is game-specific, confirm supportedGames contains only tested games.
  3. Clean installTest from the packaged folder, not source-relative files.
  4. Single-mod testVerify core behavior with no unrelated mods.
  5. Compatibility testTest likely combinations and inspect mod_conflicts.json.
  6. Archive rootThe ZIP should open directly to YourMod/, ready for antenni/mods/.

Release notes should state

  • Mod version and supported Antenni version.
  • Supported game and tested game build.
  • Install and update instructions.
  • Known conflicts and required load order.
  • Whether config formats changed.
  • Where users should send the antenni/Logs/ folder.
Do not publish your local cache

ANTENNI_CACHE_data.win is generated from the user's game and mod set. It is not part of a mod release.
