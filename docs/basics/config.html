Mod Basics

Put user-editable values in config, not hardcoded patches.

The template reads assets/data/mod-config.json into ModConfig.cs. This lets players or mod authors tweak labels and indexes without touching C#.

Current template config

assets/data/mod-config.json
{
  "verboseLogging": true,
  "enableMenuTab": true,
  "mainMenuButtonIndex": 68,
  "backButtonIndex": 69
}

The JSON can omit fields. Missing values use defaults from ModConfig.cs.

Config model defaults

PropertyDefaultPurpose
VerboseLoggingtrueExtra loader messages while testing.
EnableMenuTabtrueEnables the sample menu feature.
MainMenuButtonLabelTest Mod - EstoniaButton label.
MainMenuButtonIndex68Menu button index.
MenuTabTitleTest Mod - EstoniaTitle drawn on the custom tab.
MenuTabBodyTemplate textBody text drawn on the custom tab.
BackButtonIndex69Back button index.
BackButtonLabelBackBack button label.

Loading config

C#
ModConfig config = context.LoadJson<ModConfig>("data/mod-config.json", required: false)
    ?? new ModConfig();
Use defaults in C#.

Keep the mod usable even when the JSON file is missing or only has a few fields.

Good config values

Button indexes.Menu IDs.Feature toggles.Text labels.Debug logging toggles.Patch behavior that players may need to disable.

Common mistakes

  • Putting invalid JSON comments in mod-config.json.
  • Letting two mods use the same default button index.
  • Making config required when the mod can safely use defaults.
  • Changing config file paths without updating the C# loader path.
