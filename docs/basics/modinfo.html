Docs / modinfo.json

Mod Basics

modinfo.json controls identity, compatibility, and load order.

Every LOCLM mod should include modinfo.json in the root of the mod folder.

Recommended example

Use dependencies and load rules when your mod expects another mod or resource to exist.

modinfo.json
{
  "modName": "Example Mod",
  "authors": ["Example Author"],
  "description": "Example LOCLM mod.",
  "priority": 100,
  "enabled": true,
  "minLoaderVersion": "0.6.0-beta",
  "maxLoaderVersion": "",
  "supportedGameVersions": ["*"],
  "testedOn": [],
  "dependencies": [],
  "optionalDependencies": [],
  "incompatibleWith": [],
  "loadAfter": [],
  "loadBefore": []
}

Where it goes

The template keeps the source manifest in IncludedFiles/modinfo.json. During build, it is copied into the output folder root.

Built mod folder
MyCoolMod/
+-- MyCoolMod.dll
+-- modinfo.json
\-- assets/
The manifest belongs beside the DLL.

Do not leave modinfo.json buried inside IncludedFiles/ in the final installed mod.

Field reference

FieldUse
modNameDisplay name. Required and must be 80 characters or less.
authorsAt least one author name. Each author should be 60 characters or less.
descriptionShort mod description. Keep it under 500 characters.
priorityBase load order. Lower values load earlier unless dependency rules change order. Valid range is -100000 to 100000.
enabledSet false to disable the mod without deleting files.
minLoaderVersionWarns or blocks when the loader is older than the mod expects.
maxLoaderVersionUse only when a future loader version is known to break the mod.
supportedGameVersionsUse *, any, or prefixes of the game data.win or executable SHA256 hash.
testedOnGame build hash prefixes the mod author personally tested. LOCLM warns if the current build is missing from this list.
dependenciesRequired mods. Missing dependencies skip the mod.
optionalDependenciesSoft integrations. The mod can still load without them.
incompatibleWithKnown-bad mod combinations.
loadAfterLoad after another mod if it exists.
loadBeforeAsk LOCLM to load this mod before another mod.

testedOn and game updates

testedOn is different from supportedGameVersions. Use supportedGameVersions for builds you intend to support, and use testedOn for builds you actually tested. After a Lake of Creatures update, check loclm/Logs/game_compatibility_report.json and loclm/Logs/game_resource_baseline.json.

testedOn example
{
  "modName": "Example Mod",
  "authors": ["Example Author"],
  "description": "Example LOCLM mod.",
  "priority": 100,
  "supportedGameVersions": ["*"],
  "testedOn": [
    "PUT_DATA_WIN_OR_EXE_HASH_PREFIX_HERE"
  ]
}

Validation habits

Use a unique mod name.Keep at least one author in authors.Use enabled: false for local testing instead of deleting the folder.Declare required mods in dependencies, not only loadAfter.Use incompatibleWith for known broken combinations.Keep version fields honest so players get useful warnings.

Common mistakes

Folder and DLL names should match.

If your folder is MyCoolMod, the main DLL should be MyCoolMod.dll.

  • Leaving template names in the manifest.
  • Forgetting at least one author.
  • Using dependency names that do not match another mod's identity.
  • Depending only on priority when a real dependency should be declared.
