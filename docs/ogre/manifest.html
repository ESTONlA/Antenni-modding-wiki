Ogre / Manifest
Mod basics

Mark Ogre compatibility explicitly

The manifest is the boundary that prevents a Lake patch from being applied to Ogre Chambers 2222.

Minimal Ogre manifest

{
  "modName": "Ogre Example",
  "authors": ["Your Name"],
  "description": "An Ogre Chambers 2222 mod.",
  "enabled": true,
  "supportedGames": ["ogre-chambers-2222"],
  "priority": 100
}

Cross-game manifest

Only declare both IDs if the same DLL branches by game and every patch has been tested in both data files.

{
  "modName": "Shared Utility",
  "authors": ["Your Name"],
  "description": "A deliberately cross-game Antenni mod.",
  "supportedGames": [
    "lake-of-creatures",
    "ogre-chambers-2222"
  ],
  "priority": 100
}
A shared DLL does not make shared resources

Game IDs can share C# utility code while still requiring separate resource names, patch files, and compatibility tests.

Ordering and compatibility fields

The current loader also reads minLoaderVersion, maxLoaderVersion, supportedGameVersions, testedOn, dependencies, optionalDependencies, incompatibleWith, loadAfter, and loadBefore.

Legacy manifests

Do not rely on an old manifest with no supportedGames field for Ogre. New Ogre mods should always state the game ID so the loader can make a deterministic compatibility decision.

Common mistakes

  • Using the display title instead of the exact ID ogre-chambers-2222.
  • Copying the Lake manifest unchanged.
  • Claiming both games because the project builds, without testing both patches.
  • Using load order to mask an incompatible resource replacement.
