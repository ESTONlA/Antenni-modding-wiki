Ogre / Troubleshooting
Debugging

Debug Ogre as its own target

Confirm the correct executable and profile first, then check manifest compatibility, resource targets, and generated reports.

Loader does not start

  • version.dll must be beside ogre chambers 2.exe.
  • The proxy and game must both be x64-compatible.
  • The complete antenni/ folder must be present.
  • Windows may have blocked downloaded DLLs.
  • .NET 10 Runtime x64 and the Visual C++ x64 Runtime must be installed.

No Antenni button

This is expected on Ogre

Antenni 1.0.0 does not install the Lake-specific in-game loader menu into Ogre Chambers 2222.

Mod is skipped

Open antenni/Logs/mod_status.json. Verify enabled, disabled markers, dependencies, loader version limits, and whether a populated supportedGames list excludes Ogre. A missing list does not block the mod.

Patch target is missing

Confirm you inspected Ogre's original data.win from the same installed build. Lake names and old Ogre names are not valid fallback targets.

Game fails after cache generation

  1. Disable other modsReproduce with one Ogre mod.
  2. Clear the cacheForce a clean patch run.
  3. Read the patch errorFind missing resources, invalid GML, or failed replacement counts.
  4. Inspect conflictsCheck whether multiple mods changed the same code or asset.
  5. Restore one feature at a timeIdentify the exact failing patch.

Useful reports

Start with ANTENNI.log, mod_status.json, failed_mods.json, mod_conflicts.json, security_report.json, and game_compatibility_report.json. Share the complete Logs folder for support.

Unknown game build

An unknown build warning means the installed hash is not in the supported list. It does not prove failure, but the mod author must retest every required target and update compatibility notes.
