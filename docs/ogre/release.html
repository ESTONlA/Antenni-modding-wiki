Building and release

Release an Ogre-specific package

Build Release configuration, test the exact output against Ogre, and ship the complete mod folder with an explicit game manifest.

Build

dotnet build .\OgreExample.csproj -c Release

Package

OgreExample/
|-- OgreExample.dll
|-- OgreExample.deps.json
|-- modinfo.json
|-- UndertaleModLib.dll
|-- Underanalyzer.dll
|-- GameSpecificData/
`-- assets/

Install this exact folder under antenni/mods/. Remove development-only files only after confirming the release still loads.

Ogre release checklist

  1. Game IDManifest includes ogre-chambers-2222.
  2. No Lake hooksPackage contains no accidental CreatureProbe main-menu patches.
  3. Verified targetsEvery Ogre resource requirement resolves against the tested build.
  4. Clean cacheTest after removing the generated cache.
  5. Complete outputAssets and required dependency files are included.
  6. Known limitationsState that the current Antenni in-game menu is not installed for Ogre.

Cross-game releases

If one archive supports both games, separate GML under game-specific directories and document how the DLL chooses the correct patch set. Test both games from the same published archive.

Never include data.win or the generated cache

Distribute only your mod files. Game data belongs to the user's installation and the cache is machine/mod-set specific.
