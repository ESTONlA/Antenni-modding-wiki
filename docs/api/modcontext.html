API

ModContext is the template helper for common mod tasks.

ModContext wraps asset loading, logging, JSON config, code patching, and resource lookup so mod code stays readable.

Basic setup

Create the context inside your mod's Load method after checking audiogroup == 0. The template uses it to find the mod folder, load assets, and patch the open UndertaleData instance.

C#
ModContext context = ModContext.Create(data);
ModConfig config = context.LoadJson<ModConfig>("data/mod-config.json", required: false)
    ?? new ModConfig();

context.Log("Loaded config.");

Context properties

PropertyUse
DataThe loaded UndertaleData object being patched.
ModRootThe folder for the current mod.
AssetRootThe mod's assets/ folder.
CodeRootThe mod's assets/code/ folder.
DataRootThe mod's assets/data/ folder.
ManifestThe parsed mod manifest when available.
CodeFilesDiscovered GML code assets, loaded recursively.

Asset and config helpers

Paths are relative to assets/. For example, data/mod-config.json resolves to assets/data/mod-config.json.

MethodUse
GetAssetPathBuilds a path inside assets/.
RequireAssetPathReturns an asset path or fails if it is missing.
LoadBinaryAssetReads an asset as bytes.
LoadTextAssetReads an asset as text.
LoadJson<T>Reads and deserializes a JSON asset.
ReloadCodeFilesRefreshes the recursive assets/code/ file list.
C#
ModConfig config = context.LoadJson<ModConfig>("data/mod-config.json", required: false)
    ?? new ModConfig();

byte[] rawBytes = context.LoadBinaryAsset("sprites/my_button.png");

Code patch helpers

These are the main helpers used by CreatureProbe. Keep large GML in files under assets/code/ and call it from C#.

Patch existing code

FindReplaceCodeAppendCodeFromFileHookCodeFromFileHookFunctionFromFile

Create code

CreateFunctionFromFileCreateObjectCodeFromFile

Replace object events

ReplaceObjectEventFromFileEventSubtypeDrawEventSubtypeStepEventSubtypeMouseEventSubtypeKeyEventSubtypeOther

Token replacement

ReplaceTokensAppendCodeFromFile(..., replacements)
C#
context.AppendCodeFromFile(
    "hooks/obj_ctrl_main_menu_Draw_0.gml",
    "gml_Object_obj_ctrl_main_menu_Draw_0",
    ("__MENU_TAB_TITLE__", QuoteGmlString(config.MenuTabTitle)));
Token replacement is strict.

If the template expects a token and it is missing, fix the GML file instead of shipping a silent broken patch.

Resource lookup helpers

Use Require* when your mod depends on a resource that already exists in the game. That makes failures clear when a game update renames or removes something.

MethodResource
RequireObjectGameMaker object
RequireSpriteSprite resource
RequireRoomRoom resource
RequireCodeEntryCode entry such as gml_Object_...
RequireFunctionFunction/script code entry
RequireScriptScript resource
RequireSoundSound resource
RequireVariableGameMaker variable entry

Sprites, sounds, and included files

The template already includes helpers for common asset work. Sprite helpers are for PNG files. Sound helpers support embedded .wav and .ogg files in the built-in audio group.

MethodUse
AddSpriteFromPngAdd a new sprite from a PNG asset.
ReplaceSpriteTextureFromPngReplace an existing sprite texture from a PNG asset.
AddSoundFromFileAdd a new embedded sound from an asset file.
ReplaceSoundFromFileReplace an existing sound from an asset file.
AddIncludedFileAdd an included file from assets/included/.
RequireIncludedFileRequire and register an included file.
GetIncludedFileGamePathGet the in-game path for an included file.
Included files are shipped with the mod.

The template does not inject files into GameMaker's empty DAFL chunk. Keep included files under assets/included/.

Safe string replacement

String helpers are useful when you need to change game text without replacing a full script.

MethodUse
ReplaceTextOnceReplace one exact text occurrence in a larger string.
ReplaceTextExactReplace only when the full original text matches.
ReplaceGameStringReplace an exact game string.
ReplaceGameStringContainsReplace a game string found by contained text.
Prefer exact replacements.

Contains-based replacements are convenient, but exact replacements are safer when multiple game strings are similar.

Objects and rooms

Use these when a mod needs a new GameMaker object or needs to place an object into a room.

C#
UndertaleGameObject obj = context.CreateObject("obj_my_mod_controller");
context.PlaceObjectInRoom("rm_main_menu", obj, "Instances");

NewObject is an alias for CreateObject. AddObjectToRoom is an alias for PlaceObjectInRoom.

Usage notes

Prefer helper methods.

Use Require* methods when your mod depends on a game resource. Failing early is easier to debug than silently patching the wrong thing.

  • Keep GML snippets in asset files when they are larger than a few lines.
  • Use context.Log before and after major patch steps.
  • Keep config defaults in C# and user-editable values in JSON.
  • Prefer exact string/resource names over broad search logic.

Common mistakes

  • Calling helper methods before creating ModContext.
  • Assuming a resource exists without requiring it.
  • Using hardcoded paths outside assets/.
  • Hiding errors instead of logging them.
