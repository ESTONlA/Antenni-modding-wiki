Patching

Keep GML in files, not giant C# strings.

The template indexes every .gml file under assets/code/. You reference those files by path when appending, replacing, or creating code.

How files are indexed

ModContext.Create(data) calls ReloadCodeFiles(). That scans assets/code/ recursively and stores each GML file by relative path.

Example
assets/code/
\-- hooks/
    \-- obj_ctrl_main_menu_Draw_0.gml

The relative path used by helpers is hooks/obj_ctrl_main_menu_Draw_0.gml.

Append vs replace

MethodMeaningRisk
AppendCodeFromFileAdd GML to the end of an existing code entry.Lower risk when you only need extra behavior.
FindReplaceCodeSearch inside an existing code entry and replace text.Medium risk. Search text can change after game updates.
HookCodeFromFileReplace an entire code entry.High risk. Conflicts with other full replacements.
ReplaceObjectEventFromFileReplace an object's event handler.High risk unless you own the object.

Token replacement

Tokens let C# inject config values into GML before the patch is imported.

GML asset
draw_text(32, 32, __MENU_TAB_TITLE__);
draw_text(32, 64, __MENU_TAB_BODY__);
C# patch
context.AppendCodeFromFile(
    "hooks/obj_ctrl_main_menu_Draw_0.gml",
    "gml_Object_obj_ctrl_main_menu_Draw_0",
    ("__MENU_TAB_TITLE__", QuoteGmlString(config.MenuTabTitle)),
    ("__MENU_TAB_BODY__", QuoteGmlString(config.MenuTabBody)));
Missing tokens fail intentionally.

ReplaceTokens uses exact single-match replacement. If the token is missing or duplicated, fix the GML file.

Hook file naming

Use file names that tell you exactly what they patch.

GoodBad
obj_ctrl_main_menu_Draw_0.gmldraw.gml
main_menu_spawn_buttons.gmlpatch1.gml
obj_player_Step_0_append.gmlstuff.gml

Debug checklist

Did the file end in .gml?Is it under assets/code/?Does the relative path match the helper call?Did the build copy assets/ into output?Does the target code entry exist?Did token replacement find exactly one token?
