Docs / Patching GML

Patching

Prefer small targeted patches over replacing whole scripts.

Most LOCLM mods patch GameMaker code entries. Smaller patches survive game updates better and conflict less with other mods.

Patch types

Best

Append hooks

Add behavior at the end of an event or script when you only need to observe or extend behavior.

Careful

Find and replace

Use exact small search strings. If the game updates and the string changes, the patch can fail.

Avoid full replacements unless needed.

Replacing entire scripts is more likely to conflict with other mods and future game versions.

Find and replace example

C#
context.FindReplaceCode(
    "gml_GlobalScript_main_menu_spawn_buttons",
    "btn_yy = 4;",
    "btn_yy = 4;\n    global.button_unlock[68] = 1;");

Append GML from a file

Keep larger GML snippets in assets/code/, not inside giant C# strings.

C#
context.AppendCodeFromFile(
    "hooks/obj_ctrl_main_menu_Draw_0.gml",
    "gml_Object_obj_ctrl_main_menu_Draw_0");

CreatureProbe hook files

The sample main-menu tab uses small hook files under assets/code/hooks/. This keeps the C# entry point readable and makes each patch easier to review.

assets/code/hooks
hooks/
+-- main_menu_spawn_buttons.gml
+-- obj_button_menu_Alarm_0.gml
+-- obj_button_menu_Alarm_2.gml
+-- obj_ctrl_main_menu_Draw_0.gml
+-- obj_ctrl_main_menu_Step_0.gml
\-- obj_ctrl_main_menu_Alarm_2.gml
Use clear file names.

Name hook files after the game code entry or event they patch. Future you will know what each file touches.

Token replacement

Use replacement tokens for text that comes from config. The template uses tokens like __MENU_TAB_TITLE__ and replaces them before appending the GML.

C#
context.AppendCodeFromFile(
    "hooks/obj_ctrl_main_menu_Draw_0.gml",
    "gml_Object_obj_ctrl_main_menu_Draw_0",
    ("__MENU_TAB_TITLE__", QuoteGmlString(config.MenuTabTitle)),
    ("__MENU_TAB_BODY__", QuoteGmlString(config.MenuTabBody)));

Conflict-safe habits

Use unique global variable names.Use unique button indexes and menu IDs.Patch the smallest stable code snippet possible.Document every game resource you touch.Test your mod alone first.Check mod_conflicts.json when testing with other mods.

Common mistakes

  • Searching for text that appears more than once in a script.
  • Replacing a huge block when one line would be enough.
  • Hardcoding shared button indexes without documenting them.
  • Keeping GML patch text inside C# instead of asset files.
