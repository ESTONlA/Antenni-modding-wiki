Debugging

Use loader reports before guessing.

LOCLM writes mod status, failed mod, security, and conflict reports to help find broken patches quickly.

Important report files

FileUse
LOCLM.logLoader flow, warnings, mod load order, and patch failures.
LOCLM_summary.txtVersion, paths, hashes, warnings, and errors from a tester.
mod_status.jsonFull per-mod compatibility, load, security, and resource report.
failed_mods.jsonMods that failed metadata, dependency, or runtime loading.
mod_conflicts.jsonResources touched by more than one mod.
LOCLM_runtime.logRuntime messages written by in-game hooks.

Debug workflow

Test alone

Run only your mod first. This removes conflict noise.

Check the search strings

If a find/replace patch fails, confirm the searched GML still exists in the current game build.

Read conflict output

When testing with other mods, inspect mod_conflicts.json.

Ask for the full Logs folder

For tester reports, ask for loclm/Logs/, not screenshots only.

Common mistakes

  • Debugging with many unrelated mods enabled.
  • Ignoring a failed dependency warning.
  • Assuming the cache is fresh after changing mod files outside the expected folder.
  • Using the same button index or menu ID as another mod.
