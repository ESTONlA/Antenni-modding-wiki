Architecture

How Antenni loads a modded game

The native proxy starts the managed loader, which validates the installation, resolves compatible mods, patches a cache, and relaunches the selected GameMaker game.

Launch flow

  1. Proxy injectionThe x64 version.dll loads beside the supported game executable.
  2. Game detectionAntenni maps the executable to lake-of-creatures or ogre-chambers-2222.
  3. Install validationThe loader verifies paths, original data.win, runtime folders, and startup conditions.
  4. Mod planningIt reads manifests, compatibility, dependencies, ordering, disabled state, and security results.
  5. Patch passCompatible mod DLLs receive Undertale data through their public Load method.
  6. Cache writeAntenni writes and validates ANTENNI_CACHE_data.win.
  7. Game launchThe game is relaunched using the generated cache while the original file remains unchanged.

Mod entry point

public void Load(int audiogroup, UndertaleData data)

The loader reflects over the mod DLL for a public method with this shape. Template mods apply their main patch during audio group zero.

Cache invalidation

The cache fingerprint accounts for loader/game/mod inputs. Changes to the original game data, loader injection version, mod files, metadata, or supported-build data can require regeneration.

Why mods need supportedGames

The loader infrastructure is shared, but GameMaker resources are not. Explicit game compatibility prevents a mod designed around one data layout from being applied to another.

Reports are part of the runtime

Antenni writes human and machine-readable state under antenni/Logs/, including mod status, failures, conflicts, security results, cache state, and game compatibility information.
