In-game tools

Manage mods from inside the game

Antenni injects an independent persistent manager object into supported games. It draws its own interface and does not depend on either game's menu hierarchy.

Opening the manager

Press F10 or select the ANTENNI tab in the top-right corner. The interface remains available after room changes because its controller object is persistent.

Available actions

ActionBehavior
EnableCreates an Antenni enable override without modifying the mod manifest.
DisableSkips the mod while leaving its package installed.
Move Up / DownChanges user order while required dependency edges remain enforced.
QuarantineMoves the complete package under antenni/quarantine/mods/.
Restore DisabledReturns a package to mods/ but leaves it disabled for safety.
Open ModsOpens the main antenni/mods/ directory.
Export DiagnosticsCreates a privacy-filtered support ZIP.

Manager state

{
  "order": [
    "CoreLibrary",
    "GameplayMod"
  ],
  "enabledOverrides": {
    "GameplayMod": true,
    "BrokenMod": false
  }
}

The state is stored in antenni/mod_manager.json using an atomic write. Changes invalidate the cache and are applied on the next game launch.

Restart required

Mods cannot be safely added to or removed from the already-patched data.win while the game is running. The manager marks these actions as requiring a restart.

Diagnostics ZIP

antenni/Logs/Diagnostics/
`-- Antenni-diagnostics-YYYYMMDD-HHMMSS.zip

The archive contains text logs and reports, loader configuration, mod manifests, DLL hashes, package file counts, runtime versions, and game hashes.

Privacy filtering

Raw game paths, Antenni paths, Windows user-profile paths, user names, and machine names are replaced with placeholders. Mod DLL contents and game data are not included.

Local bridge

The injected GML communicates with the managed loader through a loopback-only TCP bridge. Lake of Creatures uses port 38520; Ogre Chambers 2222 uses 38521. Remote addresses are rejected and GML never receives unrestricted filesystem access.

Load-order rules

The displayed order is a user preference. Antenni still honors required dependencies and explicit loadBefore/loadAfter relationships.
