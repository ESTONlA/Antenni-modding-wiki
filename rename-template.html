Getting Started

Rename every public identity before releasing.

CreatureProbe is only a starting point. A real mod should have its own project name, DLL name, namespace, class name, output folder, metadata, config, and resource prefixes.

Safe rename order

  1. Copy the template folder.Keep a clean original copy so you can compare later.
  2. Rename the project file.Rename CreatureProbe.csproj and update any build commands that point to it.
  3. Update the project output.Change <OutputPath>CreatureProbe\</OutputPath> to your mod folder name.
  4. Rename namespace and class.Update every C# file that says namespace CreatureProbe.
  5. Update metadata.Edit IncludedFiles/modinfo.json so LOCLM displays your real mod name.
  6. Search for leftovers.Search for CreatureProbe and Test Mod - Estonia before release.

Search commands

PowerShell
rg "CreatureProbe|Test Mod - Estonia" .\mod_template
rg "button_index = 68|current_menu = 7" .\mod_template

The second search helps you find the sample menu IDs and button indexes if your mod adds its own menu UI.

Naming rules that prevent conflicts

Prefix new sprites with your mod ID.Prefix new objects with your mod ID.Prefix new functions with your mod ID.Use unique global variable names.Document button indexes.Document menu IDs.

Common mistakes

  • Renaming the DLL but not the output folder.
  • Renaming the class but leaving the old namespace.
  • Changing modinfo.json in source but not rebuilding before testing.
  • Shipping with template button text still visible in-game.
