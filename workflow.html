Getting Started

Build one small working mod before trying a big idea.

The safest workflow is template first, one patch second, release packaging last. This keeps errors isolated and makes crashes easier to explain.

Recommended order

  1. Build CreatureProbe unchanged.Confirm your .NET SDK, project references, and output folder work before editing anything.
  2. Install the built folder.Copy the whole CreatureProbe/ output folder into loclm/mods/ and launch the game.
  3. Rename the mod.Rename project, namespace, class, DLL, output folder, and manifest values before writing new features.
  4. Make one patch.Change one GML hook or one resource helper call. Test it alone.
  5. Add config.Move user-editable values into assets/data/mod-config.json.
  6. Package Release.Build Release and zip the complete output folder.

Daily edit loop

PowerShell
dotnet build .\mod_template\CreatureProbe.csproj -c Release
Edit C# or GML.Build Release.Copy the output mod folder.Delete stale cache only if diagnosing cache behavior.Launch the game.Read loclm/Logs/ before guessing.

What not to do first

Do not start by replacing a whole script.

Full replacements work, but they are harder to maintain and more likely to conflict. Start with append hooks or small find/replace patches.

  • Do not test with ten other mods enabled.
  • Do not copy only the DLL.
  • Do not leave CreatureProbe names in a public release.
  • Do not ignore loader warnings because the game still opens.

When something fails

Work backwards from the newest edit. If the unchanged template worked, the failure is probably in your rename, manifest, config, GML hook, or missing asset path.

SymptomFirst place to check
Mod does not appear loadedmodinfo.json, DLL name, folder name, disabled marker, dependencies.
Build succeeds but install failsOutput folder contents and missing dependency DLLs.
Game crashes on launchLatest patch in loclmMod.cs or appended GML syntax.
Menu button conflictsButton index, menu ID, and touched code entries.
