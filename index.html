Community tool / Windows x64 / 0.6.0-beta

Mod Lake of Creatures without touching the original game files.

LOCLM loads C# mods from a dedicated folder, builds a patched cache of data.win, and keeps the original game data clean.

What it does

Simple loader flow, clear files.

01

Steam starts LakeOfCreatures.exe.

02

Windows loads LOCLM's version.dll proxy.

03

The proxy starts loclm/loclm-csharp.exe.

04

LOCLM scans mods, security, metadata, conflicts, and dependencies.

05

LOCLM writes LOCLM_CACHE_data.win and relaunches the game.

Installation

Drop the loader beside the game executable.

Install LOCLM into the same folder that contains LakeOfCreatures.exe and data.win.

1

Open the game folder

In Steam, right-click Lake of Creatures, open Manage, then Browse local files.

2

Copy the release files

Put version.dll and the full loclm/ folder beside the game executable.

3

Launch normally

Start the game through Steam. LOCLM opens first, prepares the cache, then relaunches the game.

Do not replace data.win. LOCLM creates its own cache file and automatically regenerates it when loader files, mods, config files, or game files change.

Installing mods

Each mod gets its own folder.

Correct structure

The folder name and main DLL name should match.

loclm/mods/MyCoolMod/
+-- MyCoolMod.dll
+-- modinfo.json
+-- assets/
\-- dependency files...

Disable safely

Move a mod to disabled_mods/, set enabled: false, or add a .disabled marker.

Conflict reports

LOCLM tracks touched code, sprites, sounds, objects, rooms, button indexes, menu IDs, and global variables.

Blocked mods

Suspicious mods are skipped and reported in Logs/security_report.json.

Creating mods

C# DLL mods with GameMaker patch hooks.

The official template is called CreatureProbe. It adds a main menu button and a custom menu tab.

Template output

CreatureProbe/
+-- CreatureProbe.dll
+-- CreatureProbe.deps.json
+-- modinfo.json
+-- assets/
+-- UndertaleModLib.dll
\-- Underanalyzer.dll

Build command

dotnet build .\mod_template\CreatureProbe.csproj -c Release

modinfo.json

Metadata controls compatibility and load order.

Recommended fields

Use dependencies and load rules instead of relying only on priority.

{
  "modName": "Example Mod",
  "authors": ["Example Author"],
  "description": "Example LOCLM mod.",
  "priority": 100,
  "enabled": true,
  "minLoaderVersion": "0.6.0-beta",
  "supportedGameVersions": ["*"],
  "dependencies": [],
  "optionalDependencies": [],
  "incompatibleWith": [],
  "loadAfter": [],
  "loadBefore": []
}

Security scan

Basic protection before a mod DLL loads.

LOCLM scans mod DLLs for suspicious behavior. A warning can be a false positive, but it is not always false.

Reports

Security results are written to loclm/Logs/security_report.json and blocked mods appear in blocked_mods.json.

Allowlist

Only add a hash to security_allowlist.json if you trust the mod author and understand the risk.

Logs and diagnostics

One folder for support.

If something breaks, zip the whole loclm/Logs/ folder.

Troubleshooting

Common issues, direct fixes.

Check that version.dll is beside LakeOfCreatures.exe. If loclm/Logs/LOCLM_proxy.log does not exist, the proxy DLL probably did not load.

Install .NET Desktop Runtime 10.0 x64, remove broken mods, and check LOCLM_summary.txt.

Make sure each mod has its own folder with a matching DLL and modinfo.json. Check failed_mods.json.

Open mod_conflicts.json, test mods one at a time, then adjust priority, loadAfter, or loadBefore.
